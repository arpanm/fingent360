# Account authenticator

Authored 2026-09-15, pending manual validation. Migration066 adds encrypted TOTP enrollment and independent persistent management counters. Enable the existing server private-data key ring before enrollment; no new package or provider is needed. A missing key fails protected operations closed without destroying enrollment. Recovery remains available using the previously saved high-entropy recovery code even if a server key is lost.

Privacy → Authenticator security requires a current password and an already saved recovery code. Enter the displayed setup key into an authenticator app as a time-based Fingent360 account (SHA1, six digits, 30 seconds), then confirm a code within ten minutes. The key is displayed only for this setup and never saved in browser storage. Login adds an optional authenticator field for enabled accounts. Setup/confirmation/disable are owner scoped, origin checked and capped at five accepted management attempts per fifteen minutes; wrong passwords and codes consume attempts. Enabled login uses the existing committed login limiter. Used time steps cannot be replayed, including concurrently. A new unused code plus password is required to disable or rotate a recovery code. Enabling/disabling terminates other sessions. Recovery consumes its single-use code and resets password, MFA and all sessions while preserving saved records.

Connected Android uses the same UI/API. Device-only mode explicitly explains that server MFA is unavailable. Do not generate or save server secrets on a device-only request. No SMS, email or external identity provider is claimed. The current setup is TOTP, not phishing-resistant passkeys. [RFC6238](https://www.rfc-editor.org/rfc/rfc6238) supplies the time-step/replay design and Appendix B public golden vectors; six-digit output is the corresponding SHA1 truncation. Server clocks must remain accurate. Pending enrollment expires and is cleared on the owner's next status read; account deletion cascades both factor and counter rows. Operational backups/key-ring retention remain separate deployment controls.

Manual validation: configure PRIVATE_DATA_KEYS/PRIVATE_DATA_ACTIVE_KEY securely in ignored .env, run migrations with the documented owner account, restart the local application, then `pnpm sdlc "Account authenticator" --grep 'E2E-(API-1400|API-1401|API-1402|WEB-1400)'`. API1400 checks actual encrypted persistence, sign-in denial/replay and recovery; API1401 uses public RFC vectors; API1402 checks protected recovery rotation/disable and persistent limits. WEB1400 covers enrollment/reload on desktop/mobile.
