# Android native shell

Native Java Android 8+ shell loads the complete bundled Vite build at https://appassets.androidplatform.net/index.html via AndroidX WebViewAssetLoader. It is an APK, not a requirement to run a local Node server. Offline application functionality/data comes from the separately implemented offline web adapter. A current Android System WebView providing document-start scripts and origin-scoped web messages is required; older components show an update message instead of falling back to an unsafe bridge.

The shell uses origin-scoped, main-frame-checked WebMessageListener rather than addJavascriptInterface. File access is disabled, mixed content and HTTP connections are blocked, backups disabled and third-party cookies rejected. System-bar, display-cutout and IME insets pad the explicitly edge-to-edge WebView. Hardware Back calls window.__fingentHandleBack(): return true when the web app consumed it; return false to close the activity. It must return synchronously. External links require an explicit system dialog and only HTTPS/mailto intents are permitted. No intent:// execution, arbitrary file reads or native credential store is exposed.

At document start, window.FingentAndroid exposes getConfig() returning a JSON string with mode/webUrl/apiUrl, getBuildInfo(), saveFile(filename,mime,base64), and setConnection(mode,webUrl,apiUrl). saveFile allows JSON/CSV/WebM only, maximum 48 MB base64, one request at a time. It uses ACTION_CREATE_DOCUMENT and sends f360-native-result with detail {action:'saveFile',outcome:'saved'|'cancelled'|'failed',message}. No storage permission or silent filesystem write. The web layer must convert blobs explicitly and report progress/cancellation; normal input file controls use native CSV/plain-text document selection. Standard JS confirm invokes a native confirmation dialog.

Connection changes require a native confirmation and restart the activity. Defaults come from android/runtime-config.json; confirmed settings persist privately on the device. Connected mode requires HTTPS web/API origins with no path beyond / and no URL credentials/query/fragment. Offline appasset storage remains isolated from the connected origin, never automatically uploaded. Connected deployments must support HTTPS/CORS/session behavior for their selected origins. Credentials and provider keys must remain backend-side, not inside the APK.

## Build

The isolated toolchain resides under ignored artifacts/android-tools: official Eclipse Temurin 17 macOS ARM64, Gradle 8.13 and Android SDK tools. Download hashes must be verified before extraction; retained metadata/checksum files identify exact archives. AGP8.9.2, compile/target35, build-tools35, AndroidX WebKit1.14.0 and Activity1.10.1 are pinned. The build identity is com.fingent360.app version0.1.0-offline/code1.

After parent verifies and runs pnpm android:web to create dedicated artifacts/android-web with offline-build.json, run node scripts/android-build.mjs. It copies only that dedicated offline bundle into ignored native assets, builds debug APK and writes artifacts/android/fingent360-debug.apk plus build.json with SHA256/size/time. No global SDK/JDK/Gradle install is required. Build output and local.properties are ignored. This APK uses a development signing key, is appropriate for sideload evaluation, and is not a Play Store release. A production distribution needs a protected release key, versioning and release review. Future updates must retain the same signing identity to preserve installed data.

Share the APK file and its SHA256. On an Android 8+ device, authorize installation from the app receiving that file, install, then disable that installer permission if desired. Device acceptance must cover airplane-mode startup/restart, persisted workflows, CSV import, JSON/CSV/WebM export cancel/save, keyboard/rotation/system Back, external-link confirmation, and returning from connected to offline mode without data loss. Compilation does not prove physical-device acceptance. Parent records final web bundle identity and actual APK verification, never assume an earlier APK includes later changes.

Primary references: https://developer.android.com/reference/androidx/webkit/WebViewAssetLoader ; https://developer.android.com/reference/androidx/webkit/WebViewCompat ; https://developer.android.com/studio ; https://gradle.org/release-checksums/ .

The build script records the complete bundled web tree SHA256 in build.json and packages it in build-identity.txt; native getBuildInfo includes that digest. A connected main-frame load/network failure offers Retry or Use offline app, preventing a broken CDN URL from trapping access to the bundled app. The final APK uses the dedicated verified offline web bundle. Rebuild web assets before packaging subsequent changes.

Native polish includes an original vector launcher icon, an actionable WebView update screen, CSV/text document validation capped at 12 MB, and background I/O for selected document reads/writes so cloud document providers do not block the UI thread. WebView timers/media pause with the activity and resume on return. Native assembleDebug succeeded and Android apksigner validated the debug signature (v2). Final offline content/emulator evidence is recorded below; physical-phone acceptance remains separate.
