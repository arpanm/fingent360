# Official integrated-financials RSS discovery

## Specification — 2026-09-15

The official NSE integrated-filing page links the original RSS feed. Browser research verified RSS2.0 channel title, original XML link, company title, `Integrated Filing- Financials|Original|` or `|Revision|` description and offset-less item `pubDate`. Channel build time carries an offset but does not establish item timezone. Preserve the literal item time, mark timezone unknown, and never use it as a financial effective time or UTC publication time. This is a discovery inbox, not parsed financial facts, issuer identity proof, a public story or an independently reviewed release.

A separate permission gate and schedule default disabled. An authorized operator can retain an original RSS file if unattended transport is unavailable; server fetch uses only the exact linked HTTPS source with no redirects and a2MB limit. Retain immutable original body/hash, captured time and rights version. Exact item keys deduplicate repeated items; changed metadata creates a new immutable item rather than replacing earlier observations. Capture history remains reconstructible. Parser rejects DOCTYPE/entities, malformed/unexpected structures, bad original-link origin/path, duplicate items and unsupported dates/types. Invalid original XML layouts remain retained as quarantine without invented items.

Migration128 adds a gate, original captures and capture-item relationships. Operations has original upload/fetch, permission controls, paginated inbox/capture history, raw inspection and clear unavailable-identity/financial-parser state. Pagination uses observed capture time plus stable item hash, not unresolved item dates. Users may open the actual original XML in a new tab; no app CTA pretends that original download or financial parsing succeeded. Existing financial source Operations remains a separately identified manual workflow requiring an acquired original, verified security identity and a supported parser. No company mapping is guessed from display name or filename.

Existing research-auto scheduling calls the same bounded capture with a gate+schedule recheck/lock after acquisition. Same body+rights returns prior receipt; changed body produces a new capture. Transport failure is handled by durable research-run failure/retry. Same request ID is idempotent; different content/actor under it conflicts. Old captures stay private in Operations after gate disable; no public/offline evidence is created. Shared Android/iOS connected web uses this UI; offline explicitly refuses discovery acquisition and instructs reconnection.

Acceptance2000–2009: original/revision grammar and unknown timezone; malicious link/DTD rejection; real protected API idempotency and quarantine; gated scheduled acquisition with upstream-only simulated response; permission change during wait; actual browser upload/inbox/source links; equal-time pagination and offline refusal. Author only; user runs validation.
