# Historical sensitivity diagnostics

Authored 2026-09-15. Model `daily-fx-company-ols-v1` is a descriptive daily-return regression, not identified causality or an enabled portfolio forecast. It reads admitted company close observations and the published ECB INR/USD cross-rate edition; saves complete source inputs, method version, paired sample count, window, diagnostics and explicit missing requirements. Private receipts use authenticated encryption bound to account and receipt ID, are replayable by ID, exportable and deletable. Existing account deletion removes them by foreign key. The shared web/Android panel is inside Impact traces; offline uses installed source editions and local private account records only.

## Method and qualification

Minimum60 paired returns across84days, no gaps over7days, newest common date within7days, nonzero factor/company variance, no conflicting company closes, no truncated source window. Sample/window/lag thresholds are explicit application review choices, not NIST mandates. Ordinary least squares fits percentage returns with an intercept, retaining residual variance, R², lag-one residual correlation, slope standard error and an explicitly conditional normal-approximation interval. Numbers in this statistical fit use finite floating-point arithmetic; they never calculate account balances, tax or trade money. Immutable source decimals remain retained. No interpolation, invented rows, consensus, causal elasticity or forecast is created.

Primary method references: [NIST least-squares equations](https://itl.nist.gov/div898/handbook/pmd/section4/pmd431.htm) and [NIST advantages/limitations](https://www.itl.nist.gov/div898/handbook/pmd/section1/pmd141.htm). Interval assumptions include independent constant-variance errors and an adequate linear model; they are not automatically satisfied by financial observations. Serial correlation above the explicit0.2 threshold adds a warning. A historical slope is not a causal effect.

**Still missing for forecast qualification:** current exchange `price.adjusted` is always false; corporate-action capture retains exact purposes but no numeric split/bonus/dividend factor and no complete-window adjustment coverage receipt. Need verified exact action ratios, complete ex-date coverage, source provenance, an independently reviewed adjustment transformation, and empirical out-of-sample validation. Absence of a retained action does not prove no action occurred. The engine can produce diagnostic fits if enough actual history exists, but cannot honestly qualify a forecast with current source contracts. Current ECB adapter retains a rolling90-day original file; expanded paired company history and publication vintages may also be needed. These are precise data/model gaps, not an instruction to fabricate values.
