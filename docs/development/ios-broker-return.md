# iOS broker authorization return

Authored implementation; no native build, simulator/device, API test or check was run. The shared Kite, Upstox and eligible Angel publisher flows retain their existing HTTPS callbacks and owner-bound `/complete` APIs. No broker password, OTP, exchange or trading endpoint is added to iOS. Provider credentials and signing are required only for activation/physical acceptance.

After a consented preparation, shared UI arms the current native view with the exact server-created state. Only connected HTTPS **same-origin API** deployments are supported for this return path; a separate API origin is rejected with an actionable message. Configure an HTTPS `/api` reverse proxy or use the ordinary web connection. This constraint prevents a page from selecting a new native credential destination. No native cookies or API requests are used for broker completion.

The registered server callback still offers a user-clicked `fingent360://broker-kite`, `broker-upstox` or `broker-angel` link. AppDelegate forwards it only to the existing view. Exact scheme/host, empty path, absent credentials/port/fragment, exactly two nonduplicate parameters, token grammar/length, pending nonce and ten-minute expiry are checked. Unsupported/cold-start/unprepared returns are refused; restart authorization in Holdings. Receipt uses a constant notification and structured WK reply, never script interpolation of the URI. It is consumed once, cleared on reload/unmount/discard/revoke/delete, and held only in process memory. UI completion is a second explicit confirmation; server validates current signed-in owner, one-use state, expiry and version both before and after provider exchange.

**Transport boundary:** this reuses the existing callback contract carrying a short-lived request token/code or Angel authorization token. It is not an opaque handoff. Custom schemes do not prove exclusive app ownership; verified associated-domain universal links or a future opaque callback receipt would require a separate protocol/deployment change. No URI is logged or saved by this shell. Cancelling provider authorization can omit a token: the existing HTTPS cancellation page explains return/reconnect, rather than accepting malformed URI data. Changing accounts cannot transfer the pending server state.

The baseline iOS preview now has offline shared application, restricted hosted mode, native feedback capture/audio/protected queue/foreground sync and three broker returns. Native private-file export/share is now authored; physical interaction acceptance remains; production signing/distribution, background push and channel activation remain separate.
