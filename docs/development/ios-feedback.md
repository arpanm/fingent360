# iOS native feedback preview specification

Scope: shared feedback bubble → masked in-app WKWebView snapshot → crop/cover → typed or native AAC voice feedback → explicit consent → durable app-private queue → configured HTTPS delivery → actual receipt/status/delete. Offline receipt state persists across app restarts; native delivery resumes only while the app is open. No push/background entitlement, broker callback, silent cross-origin data migration or signed distribution is included.

Native bridge admission requires main-frame WK message origin and current view URL matching the packaged offline loopback or configured HTTPS app origin. WebKit reply handlers deliver structured values directly, not interpolated JavaScript. Capabilities are advertised only when that handler is installed. Native commands are a fixed feedback/media allowlist. The asset listener still exposes public bundled files only.

Store the per-origin feedback JSON envelope using AES-GCM with an installation key in Keychain (`WhenUnlockedThisDeviceOnly`), authenticated origin binding, protected atomic file writes and bounded compare-and-swap revision. Never fall back to plaintext or reset unreadable data. Voice drafts use protected temporary files and are deleted on cancellation/stop/background; queued audio is inside encrypted state. Microphone access is requested only after Record. Permission denial, interruption, unsupported bridge and storage/network failure are visible.

Native HTTPS sends are bound to the exact enabled feedback destination persisted in that origin's queue. Permit POST /feedback or receipt-token GET/DELETE /feedback/:uuid only; no redirects, cookies or account tokens, bounded payload/response,30-second timeout. Existing server validation/idempotency and shared submission/receipt schema remain authoritative. Reload/navigation cancels native recording and invalidates in-flight page replies. Foreground emits the existing resume signal; no server worker or DB migration is required.

Primary implementation references: [WK reply handler](https://developer.apple.com/documentation/webkit/wkscriptmessagehandlerwithreply), [WK snapshots](<https://developer.apple.com/documentation/webkit/wkwebview/takesnapshot(with:completionhandler:)>), [AVAudioRecorder](https://developer.apple.com/documentation/avfaudio/avaudiorecorder), [Keychain accessibility](https://developer.apple.com/documentation/security/ksecattraccessiblewhenunlockedthisdeviceonly). No build/device validation has run. Author web adapter cases and native acceptance matrix separately; browser mocks cannot prove iOS permission, Keychain or WK behavior.

## Implementation and manual handoff

`FeedbackBridge.swift` implements protected per-origin queue CAS, WK snapshots, bounded AAC recording, exact-destination ephemeral HTTPS transport and generation-bound structured replies. `feedback-bridge.js` advertises only installed capabilities. Shared feedback capture/store/voice modules now prefer the actual iOS bridge where present; Android and browser paths remain separate. iOS connection switching is not falsely offered through Android-only App settings. Source configuration still requires packaging; feedback destination is configurable in existing feedback delivery settings.

API1610 exercises the actual iOS native Origin marker, receipt/read/delete and lookalike rejection. WEB1610–1612 simulate bridge denial/stop/remove to verify shared UI recovery; synthetic audio bytes are not claimed playable native recordings. Physical IOS1612–1619 cover WK origin boundaries, real recording, Keychain, screenshot privacy, restart/offline eventual sync, CAS/error recovery and deletion. [Native matrix](../../tests/e2e/plans/ios-acceptance.md).

No dependencies, DB model or migration added. API uses existing feedback tables/encryption/idempotency. No tests, formatter, checks, project generation, build, service changes, signing or commit were executed. Current local HEAD remains a2c53a0 and the shared working tree awaits manual gates. User runs `pnpm sdlc "Add iOS native feedback" --grep 'E2E-(API-1610|WEB-161[0-2])'`, then `node scripts/ios-package.mjs` and builds the generated Xcode project manually.
