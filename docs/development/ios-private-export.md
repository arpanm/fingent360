# iOS private file export

Authored, unvalidated native parity. Existing shared account, report, feedback and financial export actions call `saveDownload`; iOS now awaits a structured native result instead of relying on a blocked download navigation. Existing owner-bound API/local export schemas remain authoritative. Export is available offline for existing local records and connected for admitted account data; no export endpoint or database migration was added.

The installed main-frame bridge accepts a safe ASCII basename (up to100 characters, no path/traversal), a supported MIME/extension and at most12MB decoded bytes. JSON, CSV, HTML reports, text, PDF, ZIP, PNG, WebM and retained XLSX are supported; other types fail visibly. Bytes never become a navigation or script. Native export invokes UIActivityViewController with a protected temporary file. The user chooses Files or another installed recipient and can cancel; cancellation throws an actionable message instead of reporting saved. A successful activity means the destination accepted the file, not proof of remote delivery or permanent retention.

Each export uses an unpredictable app-owned temporary directory, complete file protection and backup exclusion. One share sheet is permitted at a time. Completion, cancellation, page invalidation or ten-minute timeout removes only its directory; next launch removes abandoned export directories. Foreground return does not re-share automatically. Copies explicitly saved by the user or handed to another application are outside Fingent360 deletion/retention control. The app does not list external files or accept filesystem paths, arbitrary URLs or native credentials from the page.

Same-origin download anchors and bounded inline data use the same native path; cross-origin download URLs are rejected rather than fetching private material from a different host. Shared web and Android flows otherwise retain their existing behavior. Restricted iOS public-link sharing is a distinct workflow; private files are never uploaded to create public URLs.

Manual prerequisite: existing dependencies and migrated API test databases for account exports; offline physical cases need only packaged local account data. Run `pnpm sdlc "Add iOS private export" --grep 'E2E-WEB-166[0-2]'` manually, then `node scripts/ios-package.mjs` and user-owned Xcode build/sign/install. Browser cases simulate only native replies while obtaining an actual private API export. Complete IOS1663–1669 in the native plan to verify file permissions, picker, cancellation and lifecycle. Use the printed test UI URL with watch off and configured app URL; report case/run artifacts and redacted native errors, never private exported JSON. No dependency install, gates, tests, build or commit was run. HEAD remains a2c53a0 with shared uncommitted changes awaiting manual gates.

Primary platform references: [Apple UIActivityViewController](https://developer.apple.com/documentation/uikit/uiactivityviewcontroller) and [URL backup exclusion](https://developer.apple.com/documentation/foundation/urlresourcevalues/isexcludedfrombackup). Native-device behavior remains unverified; browser reply simulations do not establish file-system protection or recipient behavior.
