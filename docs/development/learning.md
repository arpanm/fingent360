# Guided plans, reusable inputs and learning (UX-002E/F)

Goals now use purpose → amounts → contribution plan → review/save. Manual holdings use identifier → quantity/cost → row review → draft, followed by the existing complete-portfolio preview/confirm transaction. Back keeps input; Save persists real account-owned data. Amounts still use exact decimal strings/integer paise. Goals never infer account balances or investment returns. The reviewed holdings record is user-entered, not independently verified or priced.

The optional Previous entry suggestions panel reads actual saved account rows through `/api/v1/account/learning/suggestions`. It shows original name, saved time and revision. Explicit Apply copies only the displayed contribution/timeline or holding record into the draft; no input changes on opening the panel. A reused existing holding edits its draft row rather than duplicating capital. Suggestions can be dismissed. There is no external AI call in this deterministic suggestion path. Empty history produces an explicit empty state.

`#learning` contains two authored glossary quizzes (ISIN identity and reconciliation) and one voluntary topic-preference poll. Question version 1 is tied to `glossary-dev001-v1`, an explicit transcription of the repository's DEV-001 glossary. The answer rubrics were checked against that text during implementation; this is not a claim of external accreditation. Correctness and explanation are calculated server-side, and owned attempts persist with question/source revision, timestamp and idempotency key. Source wording changes require a new question/rubric version; do not rewrite past attempts. Quiz history displays the latest 100 attempts, while the private export includes all stored attempts.

Polls keep one current choice per account/question/version, which the user can update. Totals come from actual saved rows, with no seeded counts. Deleting an account removes its answers and vote and reduces the live aggregate; totals describe current participating accounts, not a representative sample or market forecast. Poll updates do not retain historical votes; quiz attempts are immutable. Both write paths require the configured Origin, cookie session and explicit learning-storage consent. Quiz requests reuse the same idempotency key after a failed save/reload; conflicting reuse rejects. A per-account quiz submission limit bounds repeated writes.

New tables: `app_learning_attempts` and `app_learning_votes` in additive migration 012. No new dependency or provider key. The app exports the contracts and registers LearningController, AccountLearningController and the Learning component. Account deletion cascades learning rows; privacy export includes attempts and current votes. Public `/api/v1/learning/catalog` supplies glossary context without private records.
