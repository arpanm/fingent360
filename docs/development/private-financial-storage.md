# Private goal and holdings storage

Authored 2026-09-15; not validated or applied. Migrations070/071 add AES-GCM envelopes for goal revisions, holdings revisions and import previews. Owner/record/revision identifiers form authenticated context. Exact-decimal contracts, reconciliation, revisions, confirmations and head metadata retain their original meaning. New rows never duplicate clear payloads; legacy rows and old key IDs rewrap during admitted reads, and unknown keys fail closed. Keep every old key available until all retained rows are rewrapped; fetching a current revision does not mean all historical records have migrated. Privacy export reads all owned revisions, including removed goals, and converts their payloads transactionally. Account deletion still cascades underlying rows. Preview expiry and confirmed idempotent replay remain intact. No background job or automatic blanket backfill was executed.

All source goal/holding consumers now use shared accessors: goals, scenario adoption, holdings preview/confirm/history, overview, allocations, learning, assistance, feasibility, research connections/reviews, record reports/schedules, evidence impact and action centre. Overview retains repeatable-read snapshot semantics while allowing the same-transaction legacy encryption write. Existing API contracts preserve web/connected Android workflows. Device-only storage has its existing device boundary and is not falsely described as encrypted by server database migrations. Derived reports/schedules/connections now also have authored migrations074/075 described below; validation and legacy rollout remain manual.
