## Concrete pipeline

- Reader and feed response paths in DiscoveryStore retain the exact parsed public FeedItem payload, identified by a SHA-256 content hash and original source ID/version. Repeated views deduplicate; no per-user reading history, holdings or rendered DOM is collected. `evaluation_public_views` retains immutable records. The source table holds public source payloads; the composition extension below binds admitted media. Pixel screenshots and private UI are not collected.
- Real public event-extraction and caption calls pass through durable `preparePublicAi`/`recordPublicAi` instrumentation. A call row exists before provider dispatch. The actual `generateAssistance` boundary captures bounded raw provider JSON, including non-success responses, before provider parsing. It records returned text/timing/status. No credentials or headers are stored. Existing event receipts expose actual consumer validation outcomes; provider success alone is not accepted publication. Source and operator admission stay held through actual event dispatch start.
- Existing story_image_attempts retains image prompt/raw output and generated bytes. Evaluation view links these immutable IDs without duplicating images. Existing discovery_raw Mongo captures remain the originals and are fetched only by retained source hashes through an operator-authenticated endpoint.
- Browser reader/story flows retain the current public item plus admitted media asset/image attempt/hash and runtime context in sessionStorage. Failed navigation or leaving Stories clears stale context. Feedback submission attaches optional publicView with exact source payload, media references, runtime, kind and capture time; existing IndexedDB feedback queue persists it offline and synchronizes it with the report. This is explicitly client-supplied context, not verified evidence. Legacy reports remain valid. No unrelated private screen data is included.
- FeedbackInbox links matching reports to an embedded evaluation inspector. Operations also has filter/search, stable `(captured_at,id)` cursor, source details, raw outputs, actual event outcomes, source-version payloads, current feedback and fresh JSON downloads. Detail reads keep source admission locks until assembly and repeat operator checks after storage. Raw evidence likewise stays source-admitted through Mongo lookup. Withdrawn/missing sources hide retained content. Expired/deleted reports are queried out, not copied into an immortal evaluation table.

## Follow-up closure: composed reading and owned private history

Public compositions now persist exact source payload plus immutable media asset ID (which identifies the original captions), reviewed image attempt ID/hash and capture time. The inspector reconstructs source/captions/references from retained rows without copying image bytes into each view. Browser feedback captures the same media references and runtime/gesture context. This is still response/view-model provenance rather than pixel screenshot proof.

Private request history is now implemented as a **separate opt-in purpose** (`private-ai-history`), not enrolled by existing permission to share context with an external provider. Generic Purpose consent UI exposes its seven-day/50-request disclosure. Actual assistance calls retain owner-only instructions/input/raw/returned output and final grounded/fallback outcome only while this purpose is active. The store rechecks consent version on response; revoked/deleted history is never recreated by late output. Revocation erases stored contents; account deletion cascades; Privacy supports owner read/download/delete and overall account export. Expired rows are withheld immediately and a bounded expiry worker deletes them while API is running. Device mode has no remote AI calls, therefore returns an honestly empty history while retaining its local opt-in choice. No private transcripts enter Operations evaluation or external training.
