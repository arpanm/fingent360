## Account, automation and operational boundary

Account creation/sign-in/logout, watchlist, observation acknowledgments, privacy export, session revocation and account deletion continue to use their account APIs and existing ACCOUNT/ALERT/PRIVACY cases. Export includes the new library, learning and saved financial records; ownership/deletion boundaries must be reverified after the additive migrations.

`#ops` is a separate, directly addressed operations console, not an investor menu destination. Operator session authentication protects provider refresh, review/publish/withdraw and audit. Discovery refresh fetches the fixed Federal Reserve RSS endpoint; changed content is draft until reviewed. Macro refresh saves real provider evidence. Worker scheduling does not imply investor notification channels beyond the implemented in-app reminder path. Relevant API120, API121/122 and WEB020 definitions cover these boundaries; actual executed outcomes belong to the run report.

## Explicit unfinished acceptance

Executed integration evidence is recorded in [current verification](status.md). The SVG/WebM path uses source-bound templates followed by operator publication review. Optional provider assistance may select only complete supplied source blocks; it does not invent event imagery. The recorded integration runs inspect viewport captures, source-version binding and actual WebM decoding; physical-device playback and unsupported-browser acceptance remain open.

Production release remains gated on all three paid-provider live validations if those options are released, physical iOS/Android interaction and screen-reader checks, field performance and representative user research. Source inspection, authored tests and desktop/mobile emulation cannot substitute for those gates. Gesture conflict checks (scroll versus Stories transition, edge Back, text selection versus long press) require particular physical-device attention. Unimplemented company intelligence, valuations, broader approved sources, adaptive curriculum, push delivery and regulated advice are not completed by this UX work.

## Individual report deletion

Reports → Delete report opens explicit private-content deletion confirmation. Keep report, Escape and Back return focus without a write. Permanently delete uses the owned current version; success closes the reader and removes the card, announces capacity and preserves goals/holdings/allocations. Running work requires cancellation first; errors preserve retry/cancel. Newer authoritative polls replace removed cards, and late responses cannot restore them. The same shared UI runs on device; API224–226/WEB223–225/OFFLINE263–264 cover connected and local storage. Downloaded files remain outside application control.
