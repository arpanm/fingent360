# BEA retained-response recovery

BEA-QUARANTINE-001 supports only the fixed official BEA RSS endpoint and the existing bounded parser. Existing source rights evidence permits retained first-party RSS within the documented headline-only publication scope; this is not a new production approval. No provider request occurs on evidence viewing, revalidation or staging.

Every future BEA source run first creates an attempt. Append-only events distinguish started, complete-response retained, parsed, staged and failed boundaries. A response link is created only after Mongo persistence and read-back verification of exact URL/body hash, UTF-8 byte count and original retrieval time. Failures before a complete bounded response have no revalidation link. Legacy blobs are never inferred to belong to an attempt. An interrupted attempt can remain pending; its event chronology is shown honestly.

A revalidation request explicitly binds an attempt and immutable parser revision. It rechecks the retained response, parses with its original retrieval timestamp and stores a strict candidate receipt with exact current source-head baselines. The operator reviews candidate changes, then explicitly stages all candidates atomically. The stage locks a fixed BEA admission row and sorted source heads, rechecks operator authorization after waits, verifies every baseline and writes drafts and the staging receipt in one PostgreSQL transaction. No publication is automatic. Existing unchanged normalized observations create no duplicate drafts. A changed head requires new revalidation; historical request replay never becomes current context.

Cross-store persistence is not represented as atomic: a Mongo write without a PostgreSQL link remains unlinked, while an unavailable linked blob prevents validation. Each request ID has immutable input identity; exact repeats return original receipts and altered input conflicts. No source body can be edited or supplied through these APIs. Lists page in bounded keyset order. Explicit evidence views are protected; public history and withdrawn tombstones remain unchanged.

UI flow: Operations → BEA recovery → attempt metadata → retained body → Back → Revalidate → candidate review → Stage drafts → source review. Loading, empty, no-linked-response, failures, retry, stale head, historical receipt and401 states are distinct. Authentication denial clears protected contents; late reads cannot restore them. Local Operations remains connected-only with zero API calls; no quarantine records enter public device bundles.

Verification will cover actual isolated PostgreSQL/Mongo response links, unavailable/tampered bytes, malformed feed, exact request replay, head changes, concurrent staging, session expiry after locks, immutable original data and responsive keyboard workflows. Authoring is not a pass.
