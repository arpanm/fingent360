# BROKER-PARSERS-002 — broker capability and import admission

Status: capability and guided fallback implementation authored; five automatic broker export parsers remain unimplemented because a complete authoritative export schema and acquisition-cost reconciliation policy have not been established. This child does not complete DEV-008 or SRC-013.

## User outcome and acceptance

Holdings → Broker export help lets a user choose Zerodha, Groww, Upstox, Angel One or ICICI Direct, read its actual download instructions, inspect missing format evidence, and continue directly to the existing mapped CSV editor. This changes the existing editor mode through its discard guard; it does not create a second importer or bypass preview/replacement consent. The guide has an empty selection, keyboard-native selector, normal links, an explicit unsupported state and a disabled continuation during unavailable/busy account state. Broker selection is temporary UI state; it never becomes verified financial provenance. Connected web and packaged Android use the same bundled catalogue and code, with no provider/API traffic for the guide.

The strict versioned catalogue is shared in contracts and exposed by GET /api/v1/account/holdings/broker-capabilities. It contains public research metadata only and requires no account cookie. All five versions are null and status is format-evidence-pending. Unknown fields and invented enabled versions fail schema validation. An explicit guard refuses every unsupported named parser. Existing holdings request schemas reject fabricated broker formats before preview persistence. There is no automatic guessing from filename, familiar headers, brokerage branding, or arbitrary API JSON.

The fallback reparses selected ISIN/quantity/cost columns on server/device, requires exact row counts and acquisition totals, and sends the ordinary owned preview. Costs missing from an export require per-row user attestation from actual acquisition records; average-price multiplication remains forbidden. Confirmed history, source row receipts, version conflict/replay, export and deletion reuse existing holdings persistence. No raw personal broker file is stored, and no change to that privacy policy is implied by the separate public-source/LLM retention request. No additional table or migration is needed; reserved050 is unused. No worker, provider connection, broker credential or dependency is introduced.

## Primary research evidence and precise blocker

Read-only research on 14 September 2026 repeated official help and searched official downloadable sample/template documents. It also inspected official API documentation, rather than treating help navigation as a format specification.

- Zerodha: [dated XLSX report](https://support.zerodha.com/category/console/portfolio/console-holdings/articles/holding-report) establishes the download. [Kite portfolio API](https://kite.trade/docs/connect/v3/portfolio/) documents authenticated JSON, not the Console workbook. Complete sheet/header/preamble, quantity inclusion and exact cost-total semantics remain unestablished.
- Groww: [official update](https://groww.in/updates/updates-from-groww-tax-loss-harvesting-intraday-oco-bonds-and-lots-more) establishes a dated report. [Portfolio API](https://groww.in/trade-api/docs/curl/portfolio) is a separate authenticated JSON interface. Neither establishes the complete downloadable stock statement and exact total-cost rules.
- Upstox: [report help](https://upstox.com/help-center/how-can-i-check-my-holdings-248548/) and [holdings API](https://upstox.com/developer/api-documentation/get-holdings/) distinguish exports and authenticated JSON. The API describes total quantity, collateral and T+1 fields and average acquisition price, but does not define the exported workbook/CSV schema or an exact acquisition total. API numbers are not evidence for cost rounding in an export.
- Angel One: [holding statement](https://www.angelone.in/support/reports-and-statements/holding-statement) describes Excel with quantity and average price. [SmartAPI portfolio documentation](https://smartapi.angelone.in/docs/Portfolio) is a separate interface and yielded no readable schema in the research tool. Complete export layout, ISIN, quantity treatment and acquisition totals remain unestablished.
- ICICI Direct: [download help](https://www.icicidirect.com/faqs/stocks/how-can-i-download-a-summary-of-my-portfolio-on-website) establishes navigation. [Breeze reference](https://api.icicidirect.com/breezeapi/documents/index.html) is a separate API. Export sheet/header/quantity/cost rules remain unestablished; existing documented transfer-day-price risk still applies.

Search results for corporate shareholding-pattern filings, instrument masters, mutual-fund product brochures and third-party/private examples were not treated as customer holdings-export schemas. No private account was accessed and no API was called. Public API response examples can support a future consented API adapter; they cannot be silently represented as a verified downloadable holdings parser. The lack of an established primary layout is an evidence limitation, not proof that no public sample exists anywhere.
