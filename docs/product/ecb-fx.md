# ECB reference exchange rates — ECB-FX-001

The bounded implementation is authored; verification and actual provider acceptance remain pending the user's execution. It adds two unchanged ECB reference inputs, USD per EUR and INR per EUR, and an explicitly separate Fingent360 calculation of INR per USD. These records support currency education and source inspection. They do not feed portfolio valuations, trades, taxes, advice, alerts or Indian landed-cost calculations.

## Source evidence and selection

The [official reference-rate page](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html) publishes currencies per euro and links daily/history XML. It describes working-day updates around 16:00 CET, excluding TARGET closing days, and strongly discourages transaction use. The fixed selected distribution is [the last 90 days XML](https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist-90d.xml). A reported date identifies the observation, not its exact historical publication time. No Indian EOD, RBI/FBIL quotation or tradable price is claimed.

The [ESCB reuse policy](https://www.ecb.europa.eu/stats/ecb_statistics/governance_and_quality_framework/html/usage_policy.en.html) permits attributed reuse of public statistics, subject to its third-party exceptions. The [ECB copyright conditions](https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html) require accuracy and attribution, explicit identification of user calculations, and a free-original notice when information is included in paid products. These selected series are directly published ECB reference statistics. Public pages preserve source decimals, label the cross-rate calculation and link the free original and terms. No logo, source narrative or endorsement is copied. The [reference-rate framework](https://www.ecb.europa.eu/stats/pdf/exchange/Frameworkfortheeuroforeignexchangereferencerates.en.pdf) supplies methodology context, not a promise of transaction suitability or historical as-of vintages.

## Numerical and revision rules

Preserve positive original USD/EUR and INR/EUR decimal strings, including trailing zeros, with at most 12 integer and 8 fractional digits. Reject signs, exponent syntax, zero, nonfinite values, missing selected pairs, duplicate dates/currencies and unknown fields. Validate other currency entries' syntax but exclude them from retained numerical editions. Source date admission uses the actual retrieval day in Europe/Berlin; it does not invent exact historical known-at times.

For a matching reported date, INR/USD = (INR/EUR) ÷ (USD/EUR). Convert each input into integer and decimal scale, reduce the resulting fraction with GCD and round the output to eight decimal places, with halfway values rounded away from zero. Persist the unchanged two inputs, reduced numerator/denominator, output, precision, rounding and method version `f360-inr-per-usd-v1`. Strict runtime schemas reconstruct every derived value. No binary floating-point arithmetic or cross-date joins are used.

Each edition records exactly that capture's reported window and its first/last dates. Missing whole days remain absent; no inferred TARGET calendar or forward fill is applied. The file moves over time, so a later capture may omit a previously captured day. Editions retain `addedDates`, `changedDates` and `absentDates` relative to the previous edition. An absent date means only absent from this capture; it may have aged out and is not an inferred source withdrawal. Operator review and archived editions expose this distinction.

A missing single currency on a reported day, empty/unsafe document or future observation quarantines the whole capture. Equal selected lexical inputs and calculations reuse the original edition and advance checked-at. A change in source precision, value or reported window appends an immutable edition, including A→B→A. Precision-only changes retain identical exact ratios but distinct source evidence. Original historical publication/known-at times remain null; retrieval revisions are not reconstructed as-of vintages.

## Persistence, security and workflow

Migration 045 adds only the FX source head, immutable editions, numerical observation rows, capture outcomes and review receipts. PostgreSQL stores original text plus independent `numeric(20,8)` source inputs and `numeric(29,8)` derived values; reads reconcile those columns against immutable JSON. MongoDB retains complete original UTF-8 XML privately before numerical insertion. The receipt hash binds the fixed URL, retrieval timestamp and original text. Storage failure rolls back numerical/head changes while preserving a linked failed outcome/raw receipt when those writes succeed. Personal accounts, holdings, goals, issued reports and other source records are unchanged; no new private export or account-deletion category is needed.

Capture is an explicit authenticated operator action, with Origin checking and prepare permission. The fixed HTTPS request has no credentials, redirects or arbitrary URL, a 10-second deadline and a 1 MB byte cap. The parser also limits 20,000 XML tags, 32 levels, 92 unique dates spanning at most 100 calendar days and 60 currency entries per date. It rejects DTD/entities, unexpected qualified names, namespace rebinding and unknown fields before interpreting selected data. New captures are spaced by 60 seconds and serialized across instances; same-request replay performs no provider request. No scheduled refresh worker is added.

Publication and withdrawal bind a request UUID, current head version and retained edition. Bootstrap review is explicit. Named mode creates a proposal requiring a different approver; approval and proposal consumption commit atomically. Authorization is rechecked after source/storage waits and final writes. Source-wide withdrawal retires all earlier public editions/history/evidence. Later publication only admits editions explicitly published after that withdrawal. Operators retain protected evidence and dated review history. Replaying an old review returns its historical receipt without restoring withdrawn content or claiming a current decision.

More → Reference exchange rates, and the Macro link, lead to original inputs, a marked derived value, reported/captured/checked/reviewed dates, month/full-window tables, review history, formula and evidence. Public and operator pages handle loading, empty, error and retry. Review controls support confirm/cancel; uncertain replies retain the same request ID; a saved historical receipt remains distinct from authoritative current context. After failed refresh, new mutations stay disabled until a successful reload. Close and generation barriers fence delayed private replies; a real 401 clears private content. Retained XML is escaped text, never interpreted as HTML.

Offline reads use only admitted reviewed numerical editions. The explicit user-invoked collector verifies the source before/after collection, uses 50-item pages and refuses more than 500 editions or inconsistent pagination. On-device routes preserve exact source/calculation fields with zero API traffic and explain that capture/review require connected Operations. A disconnected old bundle learns later withdrawal only when replaced. No raw XML or synthetic rates are inserted into a product bundle during authoring.
