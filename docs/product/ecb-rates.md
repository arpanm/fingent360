# ECB-RATES-001 — reviewed numerical policy rates

This bounded SRC-008 child adds the ECB deposit facility, main refinancing operations fixed-rate tender and marginal lending facility rates. It is global educational context for Indian investors, without a predicted India-market impact, currency conversion, investment recommendation or market-return claim. The fixed-series choice and source interpretation below were made before implementation. Authoring and primary documentation research are permitted; live ingestion and deterministic verification remain user-only.

## Source and interpretation

The ECB Data Portal identifies change-date level series `FM.B.U2.EUR.4F.KR.DFR.LEV`, `FM.B.U2.EUR.4F.KR.MRR_FR.LEV` and `FM.B.U2.EUR.4F.KR.MLFR.LEV`, in percent per annum. These are change observations, not a business-day price feed. [Official key-rate series definitions](https://data.ecb.europa.eu/data/concepts/key-interest-rate?layerType=AL&tags_array%5B0%5D=Key+interest+rate)

The portal labels frequency B as daily businessweek and the selected provider identifiers as dates of changes; it also reports seven decimal places. We preserve reported observations without filling calendar gaps. [Official fixed-MRO series metadata](https://data.ecb.europa.eu/data/datasets/FM/FM.B.U2.EUR.4F.KR.MRR_FR.LEV)

Fetch only the fixed FM grouped key from the ECB HTTPS API, requesting SDMX 2.1 Generic XML, `detail=dataonly`, `includeHistory=false` and a fixed start date of 2008-10-15. The start avoids joining the earlier variable-tender MRO regime to the fixed-rate series. The provider's effective dates are retained as dates. The [ECB key-rate page](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/key_ecb_interest_rates/html/index.en.html) describes each facility and labels changes by their effective date. [API syntax](https://data.ecb.europa.eu/help/api/data), [format negotiation](https://data.ecb.europa.eu/help/api/content-negotiation), [documented query examples](https://data.ecb.europa.eu/help/api/data-examples).

An observation's original publication/known-at time is unknown here. API preparation time is a response timestamp, not a publication timestamp. Each retained edition records our actual retrieval time and parser version. Later retrieval changes are explicitly retrieval revisions; this module does not reconstruct what users knew at a historical instant, pretend retrospective values were captured in the past, or use includeHistory to claim an unverified vintage model. An empty/lost series does not become zero or silently delete a prior accepted edition.

The current view selects the last reviewed observation with an effective date on or before the displayed evaluation date in Europe/Berlin. Future-effective changes are separate. Historical values come from that reviewed edition; retrieval history compares immutable reviewed editions. A newer unreviewed capture does not silently become the current public edition. The original source remains available free of charge and is always linked.

ECB terms permit accurate attributed reuse, require disclosure when modified and a free-original notice for sold material; links open outside frames. No named-author papers, logos, images or third-party content are copied. [ECB copyright and reuse terms](https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html), reviewed 2026-09-14. No undocumented provider quota is claimed: our own limits are one fixed request per refresh, no automatic network retry, a minimum 60-second interval, a 10-second fetch deadline, 1 MB response body and 1,500 observations total. Future provider format/limit changes fail visibly and preserve the last reviewed edition.

## Contracts, persistence and workflow

Strict shared schemas define the three series, source URL, parser version, exact signed decimal percentage values, unique effective dates, source hash, retrieval edition, head version and review receipts. Parsing rejects DTD/entity declarations before XML parsing, unknown financial dimensions/series, duplicate dates, unsupported precision/nonfinite values, invalid dates, missing series, malformed/truncated/error documents and oversized inputs. Decimal values remain strings and PostgreSQL numeric; no binary floating-point calculation or rounding is used. Units and dimensions are fixed by the series key. Synthetic SDMX fixtures use primary documented structure and explicit synthetic identities/amounts; they are not captured live-provider evidence or proven current payload compatibility.

Migration040 stores one source head, immutable numerical editions/observations, durable refresh runs, and immutable idempotent publication receipts. Complete retained raw evidence goes to Mongo before a new PostgreSQL edition is committed. Failed parsing has a linked quarantine outcome; failed persistence cannot publish a partial edition. Repeated canonical data advances checked time without rewriting immutable evidence. Changed data append an edition, including A→B→A changes. Runs expose safe categories and counts, not credentials or raw exception details. Source admission is serialized across API instances, interrupted runs are recoverable, and idempotent request receipts never stand in for a new successful fetch.

Operations → ECB policy rates provides refresh status, draft/current context, edition inspection, retained evidence and explicit publish/withdraw with a reason and expected head version. Bootstrap mode uses the existing authorized direct-review compatibility path. Named mode requires separate preparer and approver identities through the shared proposal module; direct review is blocked. Approval consumes its proposal in the same transaction as the rate publication, after source locks and final authorization. Reusing a previously consumed direct-review request cannot approve a new proposal. Source reads and writes recheck authorization after their last blocking storage operation.

Public routes expose only a currently published source. A committed withdrawal closes current values, previous editions and public evidence together and retires every publication before that withdrawal. Later publishing admits only the explicitly reviewed edition; historical values and evidence are not silently re-exposed. Protected operator evidence remains available. Public evidence is a bounded projection of reviewed numerical records, not the retained raw XML. Reads hold the singleton source lock while admitting the edition, so withdrawn content cannot newly appear after a committed withdrawal. The device snapshot carries the explicitly admitted edition IDs and omits withdrawn editions. Previously downloaded/disconnected copies cannot be recalled.

## SRC-008 boundary

This child completes the authored initial numerical-onboarding path for a deliberately small official free rate family. The three facilities give readers a coherent view of euro-area policy context, alongside existing official Fed/ECB/BEA reading. The source candidates in SRC-008 are alternatives and expansion candidates; delivering all FRED/BLS/Treasury/paid families is not a prerequisite for this bounded three-series implementation.

It does not implement a numerical India-impact model, INR conversion or a causal investment conclusion. Those need a separately specified evidence/analysis policy and cannot be inferred from rate levels. No missing credential or paid licence blocks this fixed public ECB adapter. The outstanding source prerequisite is user-run first-provider payload/attribution validation and an explicit real refresh/review before any production data claim. Historical original publication vintages remain intentionally unavailable; each source-reported effective date, our retrieval time and later retrieval edition are independently visible.
