# Indian equity evidence coverage

Task: EQUITY-COVERAGE-001. Authored implementation; execution and source onboarding pending. This is a durable company-evidence workflow, not a claim that every Indian exchange dataset is already connected.

## Experience and acceptance

More → Indian equities opens a searchable company directory with 50-row keyset pages. Open a company to inspect exchange identity, exact unadjusted prices/volume, corporate-action notices, financial periods/bases/scales and dated sector/index membership. Every family has an explicit unavailable state. Source details show the original URL, retrieval and publication times, source row, source hash and immutable edition. Historical quotes are labelled; revisions are retained and shown side by side rather than silently overwritten. Escape, the company back action and browser navigation return to the list. My holdings is linked; viewing evidence never rewrites holdings or applies a corporate action.

Operations → Equity coverage lets an authorized preparer upload an exact supported CSV or normalized evidence document, record its permission basis and declared source date, retain and validate it, inspect original retained text, then publish/withdraw with a reason. Fixed-source fetching is available for NSE securities and Nifty 50 constituents. Named publication requires a different operator identity. Capture request IDs replay an identical payload and reject changed reuse; review request IDs behave the same way. A withdrawal removes that edition from connected public views and subsequent offline snapshots. Earlier installed snapshots require rebuilding/reinstallation and are dated records, not live withdrawal channels.

## Contracts and data model

`packages/contracts/src/equity-coverage.ts` defines strict versioned five-family observations, imports, editions, review commands, queues, company views and snapshots. Decimal values remain strings; volumes remain integer strings, including values above JavaScript's safe integer bound. Financial values retain their reported scale. No accounting calculation is performed. Duplicate natural keys inside one edition, unknown fields, invalid dates and financial periods extending beyond publication/effective dates are rejected. A declaration of an effective date remains a source/operator declaration, never proof of historical known-at availability. Missing publication time stays null.

The `f360-equity-evidence-v1` JSON format is a **reviewer-normalized evidence input**, not a branded exchange parser. Its body is retained exactly as submitted, with an original-source URL. The retained normalized document does not claim to be the upstream original PDF/XML. Reviewers must reconcile its values against actual source materials before publication. Actual fixed CSV sources retain their original downloaded/uploaded text.

Migration049 adds immutable `equity_editions`, indexed canonical `equity_observations` and an append-only `equity_reviews` ledger. MongoDB `equity_source_documents` stores exact raw text by SHA-256. PostgreSQL inserts only follow successful retention and parsing. A failed parse may leave a retained raw document without an edition; it cannot become public. There is no automatic source-to-publication transition, model invocation, forecast, tax calculation or portfolio mutation.

## API, authorization and offline

Public `GET /api/v1/equities?q=&after=`, `/:isin` and `/snapshot` return reviewed records only. Company detail caps at 1,000 records and declares truncation. Snapshot capture limits total rows to 100,000 and companies to 10,000, holding a SHARE lock on the review ledger so publication/withdrawal cannot mix admission states during capture. This deliberately bounded device export is not an unlimited market-history dump.

Operations endpoints: `GET /ops/equities`, `GET /ops/equities/:id/evidence`, `POST /ops/equities/import`, `/fetch`, `/review`. Named role permissions are read/prepare/approve respectively. Mutations enforce Origin and repeat authorization after storage waits. Raw source text and the permission note remain Operations-only; public records exclude preparer identity and rights notes. The connected app must have both PostgreSQL and MongoDB. The scoped import route requires a 3 MB JSON allowance while retaining a 2 MB source-text limit; other endpoint limits stay unchanged.

Android uses the same React reader and `handleEquityCoverage`, with `equityCoverage` supplied by the public snapshot endpoint. No provider/network calls happen in this device handler. Missing or unreadable bundles are explicit; connected source preparation cannot be performed offline. Refreshing web code does not update a previously installed APK.

## UDiFF source format and reconciliation

Schema read on 2026-09-14: [NSE workbook dated June 30, 2026](https://nsearchives.nseindia.com/web/mediaattachment/2026-06/UDiFF_trade_and_Bhavcopy_file_formats_20260630115803.xlsx), sheet “Bhavcopy File Format”, exact 34 columns. Workbook SHA-256: `b9f2fa369af20381374cdb40c3ebc96c43029401e057225599cfe63b288ba3e8`. [Official sample archive](https://nsearchives.nseindia.com/web/sites/default/files/inline-files/Bhavcopy.zip) SHA-256: `786a5ae1329f27a4f08af794737cb380e82de6a53db6751b518d2309512130fa`; its cash-market header matches the schema. Repository fixture `equity-udiff.csv` is independently synthetic, schema-attributed, and contains no copied market prices.

[Official report metadata](https://www.nseindia.com/api/daily-reports?key=CM) confirms the dated archive path `https://nsearchives.nseindia.com/content/cm/BhavCopy_NSE_CM_0_0_0_YYYYMMDD_F_0000.csv.zip`. The filename, trading/business date, NSE/CM/STK fields and EQ series must reconcile. Supported records require INE equity identities; other series/instrument identities are excluded with reconciled source counts. ISIN, symbol and instrument ID must be unique within each file. This is source-internal identity reconciliation; a separate historical security-master crosswalk is not yet enforced. A price-only company explicitly shows its missing master family rather than inventing listing data.

Prices preserve up to six decimal places, quantities up to 25 integer digits. Traded open/close/last must lie within low/high and positive volume requires nonzero trades. No rounding, adjusted prices or derived market accounting is introduced. Reserved/irrelevant columns, changed headers, mismatched dates, duplicate identities and malformed numbers reject the edition. The archive reader accepts one exact named CSV, stored or deflated, with reconciled ZIP headers, CRC and 2 MB compressed/expanded bounds. Streamed/encrypted/multi-entry/ZIP64 variants reject explicitly. Raw ZIP bytes are retained as base64 under SHA-256 in MongoDB `equity_source_archives`; the edition binds archive and decoded CSV digests, both checked before publication. Uploaded extracted CSV retains only that original CSV, not an invented archive receipt.

Operations offers file import and fixed-date fetch; company pages display exact OHLC, and search finds source symbols/names even before master ingestion. Shared web/Android contracts preserve the same quote detail in offline snapshots. Source permission remains a prerequisite. Schema/sample research is not evidence of production ingestion or provider permission. API902, WEB902, parser golden and archive integrity cases are authored; not executed.

## NSE corporate-action CSV adapter (2026-09-15)

Operations → Indian equity data → NSE corporate actions CSV accepts the official download's nine columns, preserving free-text purpose, ex-date, record date and book-closure dates. Uploading requires an explicit permission basis and prior reviewed NSE symbol/series identities. Missing/ambiguous identities, unknown headers and invalid dates reject the whole capture; retained source remains available for diagnosis. Every action stores the identity edition/hash used for the join. A source capture date is not an ex-date; future announced ex-dates are accepted without treating them as completed adjustments.

Mongo raw documents and PostgreSQL migration049 editions/observations/reviews are reused. Replays return the original edition even if identity coverage later changes. Reader company details display ex-date/record/book closure and retain source links. The same contracts/React view and exported snapshot serve packaged Android/offline; Operations capture remains connected-only. No inferred dividends, stock split factors, adjusted-price history or portfolio mutations are created.

This parser is authored against the official page's documented headings and date presentation; a representative downloaded CSV has not been executed. Automatic fetching is not enabled for this parser: no stable supported anonymous endpoint or redistribution licence is claimed. ## NSE rendered Integrated Ind AS financials

The dedicated HTML adapter extracts revenue from operations and total period profit for each reported income-statement column from the official rendered report. It preserves INR scale (rupees/thousands/lakhs/crores), quarter/year-to-date boundaries, audit status, basis and exact signed decimal strings. It rejects unsupported units/layouts and never infers a total from component rows. Source row identifies the row within the first financial-results table. Other facts remain retained in the original source but are not admitted as normalized metrics.

Choose NSE Integrated Ind AS financial HTML in Operations, enter the exact original `nsearchives.nseindia.com/corporate/ixbrl/INTEGRATED_FILING_INDAS_..._iXBRL_WEB.html` URL, upload the saved report and confirm deployment rights; retain/review/publish.
