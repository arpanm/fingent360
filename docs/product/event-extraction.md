# Source-bound event drafting — EVENT-EXTRACTION-001

The authored workflow turns one admitted retained published release into exact excerpt selections, then requires human context and confirmation before creating an ordinary event draft. Publication remains a separate existing review. User-run validation is pending; no provider call, migration, browser verification or gate was executed during authoring. This supplies the candidate-extraction workflow in DEV015/020. Entity adjudication, causal analysis, numerical policy and automatic publication are separate work.

## Workflow and source entitlement

Operations → Event review → **Prepare event from a source** opens the existing bounded publishing queue filtered to published sources. Its pages contain at most20 source summaries with a filter-bound cursor; search and further pages do not load the unbounded legacy source array. The parent event workspace initially reads only its bounded event list; ordinary source/identity choices are deferred until Create, Open or explicit Refresh. A failed choice refresh preserves the existing draft. Sources without a retained hash cannot be selected. The preview shows the exact bounded title, summary and body that optional excerpt selection receives, together with retained source identity, edition and a link to its current public reading page.

The explicit request UUID binds source ID, version, hash and method: `template`, `auto`, `openai`, `gemini` or `anthropic`. The server reads the retained source through existing publication admission, never a user URL. The fixed method is `event-extraction-v1`. A source or provider response is data, never an instruction to execute tools or change application policy. No private account context, arbitrary URL, credential, entity link, date or claimed effect enters the selection request.

The keyless template copies the source title and one exact excerpt. Title is bounded to200 UTF-16 units with a visible truncation flag. Material contains the first200 title,1600 summary and4000 body units without splitting a surrogate pair. Template selection uses the first usable field in body → summary → title order, preserving at most800 units. A usable excerpt has at least8 units. Original text is not rewritten. A candidate reserves a server-created event identity but creates no event row.

Optional AI can return only one or two strict `{field,start,end}` ranges within this material. Offsets count UTF-16 units, end exclusive; each selection has8–800 units, complete Unicode characters, and nonoverlapping ranges in the same field. Quotes are reconstructed from the retained source. Generated prose, classifications, dates, tools, links and effects are rejected. Candidate reads reconstruct a currently admitted candidate from its saved ranges and source before returning it.

## Bounded provider behavior and truthful outcomes

The existing private `generateAssistance` transport supports configured OpenAI, Gemini and Anthropic fixed hosts. It has a12-second abort deadline, no tools/chat storage, redirect rejection and a64KiB transport response cap. Serialized source material is limited to24KiB UTF-8; extraction JSON is limited to8KiB. No new dependency or provider transport is introduced.

Template preparation bypasses remote concurrency and quota. Remote preparation has one advisory-locked slot across application instances and at most20 starts in a durable hourly window. Busy or exhausted allowance fails before inserting another attempt. Missing configuration yields `not-configured` with a template candidate. Provider failure or invalid selection yields a template candidate explicitly labelled `provider-failed` or `invalid-selection`, retaining truthful attempted provider/model metadata. Only validated offsets produce `model`. The service stores no arbitrary provider output, raw error, key or provider request URL.

The first transaction admits source and operator permission and commits a running receipt. A second short transaction rechecks source and permission before starting a configured transport, then releases its locks without waiting for the response. The final transaction reacquires source admission and current authorization before retaining a candidate. Source change before dispatch remains a failed `source-changed` outcome even if a later head becomes readable again. Change, withdrawal or removal during the remote operation prevents a current candidate. Already-started bounded calls are drained; they cannot publish anything.

A completed receipt is immutable. Reusing its UUID with identical input returns the stored outcome before quota or provider work; different input returns409. A running receipt whose process-held request lock has disappeared becomes `interrupted` on explicit retry, rather than repeating an uncertain remote call. Storage/interruption failures retain safe outcome metadata where storage is available. If final failure persistence itself fails, a later same-ID retry reconciles the surviving running receipt.

## Human decision, revisions and authorization

The guided form requires explicit title, family, geography, claim kind, explanation and review reason. Unsupported announced/effective dates remain null; context links are empty. The confirmation previews the human context and retained excerpts and offers cancellation. The initial draft must preserve **all exact candidate citations in their retained order**, including count, field, quote, source identity, version and hash. Another genuine quote from that source is insufficient. Supported extra context belongs in a later ordinary event revision.

Acceptance locks the extraction request and invokes the existing `EventStore.saveIn` at expectedVersion0. The event head, immutable revision, ordinary request receipt and extraction decision commit atomically. Source/session permission is rechecked after blocking storage/evidence admission and after final decision persistence. A declined candidate creates only a dated decision. A changed/withdrawn source can still be declined as a historical editorial choice; it cannot create a draft. Same-decision replay is historical; a second differing decision conflicts. Neither path publishes or creates a proposal automatically.

Named operators require read permission for inspection and prepare permission for extraction/decisions. The shared guard and Origin policy also apply. Draft publication uses the existing independent named approval workflow; bootstrap mode uses its explicit separate review. Auth callbacks use the current transaction client rather than obtaining nested clients from the same pool. Acceptance lock order is extraction request → event identity/head → source/security admission → final authorization.

Migration047 stores `event_extraction_requests`, immutable `event_extraction_decisions` and the singleton remote allowance row. Existing retained source/evidence storage and event revisions are reused. Operator receipts are application research records, not private account records: no account export/deletion category or financial data mutation is added. Protected historical excerpts remain inspectable after source changes; no extraction public endpoint or offline candidate export exists. History uses20-item UUID-keyset pages, with no chronological snapshot or completeness claim across concurrent inserts.

## Experience and local behavior

The UI displays loading, empty source/history, setup failure, configuration fallback, provider outcome, stale source, retry and saved receipt states. Unconfirmed mutations retain the exact request identity and body, including a busy409 retry. Check saved extraction receipt reconciles an uncertain request without generating another UUID. A schema-valid response for another extraction or decision does not confirm this request. Validated receipt/current-source status is separate from the historical outcome. Failed authoritative status refresh keeps the receipt and human input but disables draft acceptance until explicit successful recovery. Decline stays available for a retained candidate.

Title-only or explanation-only edits trigger the same departure guard as other human context. Keyboard controls have visible focus; confirmation moves focus to its heading. Source preview and excerpts wrap on narrow screens, with stacked controls and minimum44px actions. Back invalidates pending draft-opening generations. Accepted decisions remain visible if reading the created draft fails, with a retry to open the actual stored revision. The shared Operations request barrier clears protected state after an actual401 and prevents late successful responses from restoring it.

On-device Operations explains that preparation requires a connected server. All local extraction read/mutation routes return503 without network or personal-state changes. Already published events continue through existing current-source-admitted snapshot paths. No candidate, model output or draft is added to a device bundle. There is no new background worker, timer, provider scheduler or automatic publication.
