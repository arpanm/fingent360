## Authored implementation boundary

A separate immutable plan binds original published head revisions and complete replacement editorials. Saving never creates output event rows. Plans are retained, paged20 at a time by UUID, and have no lifetime shutdown or automatic expiry. Local unsaved drafts can be discarded. A saved plan cannot be erased or mutated: named proposal rejection preserves it, and an explicit new proposal request is needed for reconsideration. The saved plan view and named target inspection show the same exact original/replacement fields, quotes and stored provenance. Neither implies sources are still current.

Application serializes each plan, then sorted original/output event identities, then all referenced source and security heads. It rechecks the final operator admission. All published output rows, immutable revision bodies, the application receipt and membership links commit together; any failure rolls them all back. Independent approval uses the existing named proposal completion transaction and distinct named identities. Bootstrap mode retains its explicitly labelled local single-operator workflow. Existing plan/application replays return historical receipts; a consumed bootstrap receipt cannot complete a new named proposal.

A superseded original keeps its unchanged published revision and can still be withdrawn. It cannot be edited or republished as current context. Each new UUID output can later become an input once, making an acyclic chain with at most one predecessor and one successor relation per event. Public readers show safe replacement/original links only when the target's own evidence and identity revisions are currently admitted; source withdrawal does not expose its old body. There is no reassignment of private links, holdings, reports or goals. The first guided authoring step carries explicit excerpts from selected originals, clears contextual links, and requires edited output review; additional reviewed instrument/sector context can be added with the ordinary event editor after application.

Offline mode reads captured public lineage only; editorial writes require connected Operations. Snapshot capture compares publication material and lineage before/after capture, then reconciles target titles against the actual exported corpus. This is bounded sequential reconciliation, not a cross-service atomic snapshot. Later local source/identity admission also hides unavailable target titles. A refreshed/reinstalled snapshot is needed for newer server changes.
