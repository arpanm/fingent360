# EVENT-REVIEW-001 — source-bound editorial event exploration

An event is a versioned editorial record, not an inferred market shock or recommended action. Researchers explicitly author a title, family, geography, claim kind, effective/announced times and explanation, select one to five actual currently published stored source editions, and quote exact substrings of their publicly disclosable title/summary/body. The API rejects changed editions, withdrawn sources, altered hashes and invented excerpts. No external fetch occurs. Operator-only retained originals cannot be republished by quoting them through this workflow.

Optional sector labels are explicitly researcher-authored context, not a verified classification. Optional instruments must bind a currently retained unambiguous Indian equity security identity revision; no automatic name, sector, exposure, valuation or effect is invented. A maximum of ten context links names the sector or identity, gives an editorial rationale and identifies its supporting source excerpt. The generated strict DomainEvidenceGraph uses unknown direction and an explicit context-only mechanism. It does not assert positive/negative impact or a causal transmission path. Unknown impact is visibly unavailable.

The adapter between existing discovery string IDs and UUID domain-document references is explicit in each persisted record: every source binding carries its own document/evidence UUID, source ID, version, content hash, field and exact quote. The server constructs document/event/node/edge references and validates the complete graph; clients cannot submit an arbitrary claimed graph. UUIDs identify captured records, not source identities. Claim kind stays distinct from the underlying source document kind.

Migration041 adds event heads, immutable revisions and immutable review receipts. Draft saves require an expected head revision and caller-supplied request UUID, with exact replay/conflicting-ID detection; editing never changes the published revision. Bootstrap mode supports explicit operator review. Named mode requires a distinct named reviewer through the existing publication proposal machinery. Publication takes the event lock, sorted source locks and sorted security identity locks, rechecks current evidence plus wall-clock operator authorization and completes the proposal receipt in the same transaction. A stale binding must be edited/reviewed again; withdrawal remains possible without republishing stale originals. Public history preserves dated metadata and never bypasses source-withdrawal admission.

Public event list/detail allows family, sector and ISIN filtering, and explicit links to existing source readers/security identity views. Reader headings, dates, claim-kind labels and context link wording keep facts, editorial inference and unknown impact separate. Loading, empty, error/retry, changed/withdrawn, Back and keyboard/mobile states are part of the feature. Lists/history use bounded pages; no silent partial check or invented total is presented.

Offline snapshots contain only currently publishable records captured at the actual snapshot time. Local routes validate their source bindings against the installed publication bundle on every read, with no provider/API call. Operator editing/review remains connected-only. Public snapshot export contains no operator password/session or investor data; no account-specific event records are created, so account privacy/deletion behavior remains unchanged. Older snapshots cannot claim later source freshness or live withdrawal knowledge.

Acceptance: real isolated stored sources/security revisions with clearly synthetic editorial input; exact excerpt rejection; stale/withdrawn source refusal; draft versus independently approved public state; immutable revisions/replay; role/owner/session wait admission; public filter/detail/context navigation; no causal assertion; offline snapshot read and zero network; source-version invalidation and bounded history. API/WEB/OFFLINE700–719 reserved. Authored is separate from verified; no tests, builds, migrations, services, providers or commits run by the agent. This child advances event/entity exploration, not a numerical causal model or the separately gated oil-shock policy.

Context-only edges use `horizon: null` for unknown/not applicable, not a zero-day impact horizon. Existing quantified domain-edge horizons remain explicitly bounded when present. Every publication or withdrawal appends a new head revision; public history includes only reviewed publication/withdrawal metadata, while Operations history includes candidate drafts.
