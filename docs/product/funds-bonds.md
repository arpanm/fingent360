# Funds, bond cashflows and deposit comparisons

Task FUNDS-BONDS-001 / DEV022. Specification and implementation authored; source onboarding, migrations and validation are pending. This child adds an AMFI NAV reader and owned dated-cashflow comparison. Full mutual-fund look-through and production bond-market coverage remain open.

## User workflow

More → Funds and bonds opens public fund search by name, AMC or scheme code. Each distinct AMFI scheme is kept separately, including direct/regular and growth/reinvestment variants. Details show the unrounded NAV, observation date, AMC/category, both supplied ISIN fields and retained retrieval history. Missing NAV stays unavailable. Details disclose that portfolio holdings/look-through are not connected; no exposure is inferred from a fund name. Back/Escape returns to the list, and keyset navigation limits each page to50 records. Loading, unavailable, retry and empty states are explicit.

The Bond & deposit comparison tab accepts the user's actual quote and instrument terms: clean purchase amount, settlement, previous/next coupon dates, coupon amount for that interval, fees, future net cash receipts including redemption, credit source/date or unknown, and a same-horizon deposit interest/deduction assumption. Inputs are in rupees/percentages; they are converted exactly into paise/basis points. Review shows accrued interest, dirty/outlay amounts, total receipts/net gain, numerical XIRR, duration estimate and deposit maturity. Saving requires explicit consent and stores both the complete input and final view result. Saved receipts reload, can be reopened, copied into a new editable comparison or removed. Editing never overwrites an issued comparison.

No bond issuer quote, verified credit rating, default probability, guarantee or suitability judgement is supplied. No buying/selling or recommendation action exists. Expected cashflows are user assumptions, not source-verified realized payments. Net bond receipts must include the costs/deductions the user knows; comparison disclosures identify exclusions.

## Mathematics and precision

- Cash accounting is integer paise using BigInt. Decimal rupee input accepts at most2 fractional digits; values are not silently rounded on entry.
- Accrued coupon equals supplied coupon × actual elapsed days / actual days between the supplied previous/next coupon dates. Half-up rounding occurs once to paise. The screen requires users to verify this convention against the instrument; it is not a universal Indian-bond convention.
- Dirty price adds accrued coupon to clean amount; total outlay adds supplied fees. All future receipts are summed exactly. There is no guessed coupon schedule or guessed redemption principal.
- Deposit uses simple ACT/365 interest on the same initial outlay through the last bond receipt date. Interest and its explicitly assumed deduction each round half-up to paise. This is not a quoted bank product, compound deposit or determination of tax law.
- XIRR nets same-date amounts exactly, sorts dates, then evaluates ACT/365 discounted cashflows numerically. A conventional series with a single sign change has at most one finite root. A same-sign/net-zero-date series reports no usable root; more than one sign change reports **non-conventional**, meaning multiple or no roots are possible and no single yield is asserted. It does not falsely declare every such series to have multiple roots.
- The search interval is -99.9999% to100000000% annual rate. Log-scaled NPV avoids discount overflow. Bisection is bounded220 iterations with a relative rate-width tolerance; unresolved/out-of-range results are explicit. The displayed8 decimal percentage places are numerical precision, not exact algebraic accounting or guaranteed financial accuracy. A zero net conventional series returns exactly0%.
- Macaulay duration is the discounted cashflow-weighted ACT/365 time using the calculated annual rate, displayed to6 decimals. It remains unavailable when yield is unresolved. It is not modified duration, an interest-rate stress scenario or a liquidity/credit measure.

Golden synthetic tests establish integer accrual/outlay/deposit results and conventional, non-conventional and no-root boundaries. None of their values are market fixtures.

## Data, authorization and lifecycle

Migration055 creates immutable NAV editions/observations and append-only review decisions, plus account-owned comparison rows. MongoDB `fund_nav_raw` stores submitted/fetched source text by SHA-256 before parsing. PostgreSQL stores exact normalized NAVs separately from metadata. Invalid retained text cannot become public. Publish verifies raw integrity and named mode requires another operator identity; withdrawal removes the edition from connected reads and later snapshots. Request IDs replay identical captures/reviews and reject changed reuse. Authorization is repeated after storage waits and mutations check Origin.

`GET /funds`, `/funds/:code`, `/funds/snapshot` expose admitted metadata and observations without operator permission notes. Public readers retain prior admitted observations when a later file lacks a scheme; absence is not silently interpreted as closure. History is bounded500 per scheme and declares truncation. Snapshot generation locks the review ledger during capture and packages at most5,000 latest scheme records, along with total count and truncation. It is dated, bounded device coverage; a complete historical database is not embedded in the APK.

Operations exposes queue, original text, capture/import and publication/withdrawal. A4MB source bound is complemented by the scoped HTTP JSON bound. Source capture is connected-only. Private `GET/PUT/DELETE /account/bond-comparisons` uses account ownership and an account row lock, immutable request identity, max100 live receipts and deletion tombstones. A deleted receipt cannot be recreated by replay. Raw personal input is removed on deletion; only an irreversible fingerprint remains for replay prevention. Account deletion cascades rows. Privacy export includes retained comparisons.

The Android app shares this React UI and contracts. `handleFundsBonds` uses the dated public snapshot; owned comparisons are stored through the existing IndexedDB workspace dispatcher and survive restart. Device export/deletion use `localBondComparisons`; no private inputs or provider calls are sent while offline. Rebuilding/reinstalling is required to update an installed APK. Existing snapshots are not silently live-validated after a source withdrawal.

No LLM is invoked by this feature, so LLM call/output storage is not applicable here. The source text, normalized versions, saved user input and final calculated comparison are durable and can be referenced by the separate evaluation system without treating financial estimates as facts.
