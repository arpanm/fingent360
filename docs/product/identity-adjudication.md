# Reviewed candidate selection — IDENTITY-ADJUDICATION-001

Implementation authored; validation pending. This is the bounded entity-adjudication workflow in DEV015/020. It allows an accountable editorial choice among actual retained candidates; it is not independent corporate-identity verification or completion of the exchange/security-master source task.

## Evidence and meaning

Preserve every OpenFIGI provider response, identity revision and its matched/ambiguous/unresolved state unchanged. A reviewed selection is a separate record binding ISIN, provider revision/hash, complete selected candidate fingerprint, human rationale, actor/review/time and any actually retained supporting evidence. Empty candidate sets cannot yield a selection; candidates cannot be typed or generated into existence. Provider evidence proves membership in its response. Without an authoritative retained source explicitly connecting the instrument and ISIN, display the decision as editorial judgement, never externally verified identity.

The public detail must show provider state and reviewed selection side by side, with distinct evidence/timestamps. No silent promotion of ambiguous to matched. Do not feed these selections into valuations, holdings identity replacement, recommendations or trades. No private records change.

## Lifecycle and consumers

Researcher compares candidates and saves exact immutable proposed input. A different named operator inspects complete candidate/provider/rationale evidence before approving; reject/withdraw/history and same-request replay are explicit. Bootstrap compatibility must be an explicit separate operating mode, never a named bypass. Canonical locks serialize provider-head, selection-head and support-source changes; final authorization uses current time and an existing transaction connection. Revalidate provider revision and all actual supporting evidence after waits. Stale or withdrawn decisions remain historical and unusable.

Extend event instrument references with an explicit basis that distinguishes existing unique provider matches from exact approved editorial selections. Preserve old event revisions; new revisions retain underlying provider data and selection receipt, and reconstruct graph labels from that precise chosen candidate. Standard and lineage/extraction event flows must use the same admission. Withdrawal/change of selection/provider/supporting evidence suppresses affected public event content until a new review. Snapshot/local handlers retain only admitted selections/relationships and label captured-date limitations. No old private connection/report is rewritten.

## Authored implementation choices

The first version deliberately uses only actual retained provider candidate membership as factual support. Rationale is reviewed editorial judgement; it does not create a claim of outside confirmation. The provider endpoint/hash and full retained candidate record remain inspectable; an unavailable raw response is shown as an error, not silently fabricated. No supplemental third-party identity-verification source is claimed. An unresolved empty set cannot be selected.

Immutable plans bind an expected selection-head version, provider revision/hash, exact candidate and `select` or `withdraw` action. Approval produces an immutable versioned public receipt. Named proposals supply distinct-identity authorization/decision history; bootstrap mode is explicitly single-operator. Withdrawal can target an already stale approved selection using its retained provider edition, so changed or empty newer provider results cannot trap the user. Rejecting a named proposal leaves the current selection unchanged; reconsideration uses a new proposal request. Same-plan review replay is historical and does not reactivate a later withdrawn decision.

Instrument links may contain the complete strict `selection` receipt. Existing provider-only links remain unchanged and still need a unique match. Selected links retain the unmodified provider identity, reconstruct labels from the exact chosen candidate, and require the current approved selection when saving/publishing/reading. Shared event admission also covers lineage and extraction. Withdrawing or changing a selection invalidates dependent public event content; it never rewrites event revisions, private reports, holdings, goals or research links.

Operations supplies candidate comparison, rationale, review/Back, immutable saved-plan inspection, explicit bootstrap application or named submission, and saved-plan pages. A definitive stale-base conflict requires explicitly discarding the draft and reloading; uncertain saves retry their original body/ID. Public detail separates provider ambiguity from current/stale/withdrawn judgement and pages its public receipt history20 at a time. No operator identity-management metadata is included in public receipts.

Snapshot capture checks exact provider membership and current selection before/after complete history paging. It refuses a history over1,000 records instead of silently truncating; this is an explicit installed-package size bound, not a server lifetime write limit. Offline events check captured selection and provider bindings and never contact the provider or API. New packages must be captured/rebuilt/reinstalled to receive later approvals/withdrawals. No global atomic capture or immediate offline revocation is claimed.
