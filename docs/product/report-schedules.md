# Opt-in saved-record schedules

Schedules create plain v1 saved-record reports only: owned goals, holdings and allocations, exact recorded cost and contribution-only planning. Research notes, provider requests, email, push, investment returns and advice are excluded. Consent is explicit before the first save and each configuration change. Configure label, daily/weekly cadence, local time, IANA timezone and weekly weekday, review, then save. Pause, resume, edit and delete use expected versions; receipts are historical until a successful current reload.

A timezone fold uses the first occurrence; a missing wall time advances to the first valid minute on that local date. One latest due occurrence is captured after an interruption; earlier occurrences are counted as skipped, never backdated. Capture time is the actual execution time. Editing or resuming starts from the next future occurrence. Pausing/deleting blocks new occurrence claims after commit; already-queued reports remain independently owned and removable. Deleting a report never recreates its occurrence.

Limit five live schedules. Configuration editions, operation receipts and occurrences remain immutable without lifetime shutdown thresholds. Current lists show live schedules plus bounded recent deleted schedules and 100 recent outcomes. History/export reads use keyset pages of at most 100 records per collection, with a frozen upper cursor; the dedicated download and account-export UI follow all pages before saving. A failed page never produces a purported complete download. Pause and delete remain available regardless of history size. Full report capacity records a skipped occurrence and naturally tries the next scheduled occurrence after space is freed; it does not pause or mutate schedule configuration. Configuration edits and request-ID replay are immutable until account deletion. Each occurrence has a unique schedule/edition/due key, deduplicated transactionally under the account lock. Report history capacity and hourly new-request limits remain unchanged. Snapshot and report job insertion commit atomically with the occurrence; ordinary existing leased report workers perform issuance. A crash before commit leaves no occurrence and can retry; after commit it cannot duplicate capture. No separate long-running schedule lease is needed because scheduling has no external effects and completes inside one transaction with SKIP LOCKED ownership.

On device, the serialized local transaction materializes only the latest due work when schedules or reports are opened. There is no promise of background execution while the app is closed. Connected and local schedules are separate; no synchronization is claimed. Export includes configuration editions, operation receipts and occurrence outcomes; account deletion removes them. Snapshot labels and errors contain no source text or raw database errors.

Acceptance requires timezone/fold/gap unit fixtures; real concurrent-worker deduplication; exact owned snapshot capture; missed runs and capacity outcomes; stale/foreign/revoked edits; immutable replay versus authoritative state; pause/delete/report tombstones; complete keyboard/mobile review and recovery; offline no-network next-open persistence; export and account deletion. Authored acceptance is not a test pass.

Next-run dates are rendered in the configured IANA timezone and name that timezone. Historical occurrence timestamps name the viewing device timezone; they do not silently relabel a historical configuration.
