# RESEARCH-AUTO-002 — automatic research capture

Existing enabled free sources start on a six-hour cadence after migration and API startup, with a durable per-source pause and hourly-to-weekly interval. The user explicitly requested automatic news capture. A dedicated runtime switch disables automatic work in isolated tests; no jobs are executed during authoring. A minute worker selects one due source, obtains a database session advisory lock, records a durable attempt and invokes the existing raw-retaining discovery adapter. Crash recovery marks the unfinished attempt interrupted, then safely repeats content-addressed ingestion. Failures retry after 15 minutes. Pausing affects future claims; an already claimed fetch may finish. The same enabled-source and publication gates apply to manual and automatic refresh. New drafts enter Publishing; approved records enter Today/Explore/Stories through the existing feed. Automatic fetching does not mean automatic editorial approval.

The fixed BEA official calendar is a separate eligible source. Preserve exact downloaded bytes in Mongo, immutable parsed editions in PostgreSQL, and schedule timestamps/UID/SEQUENCE/cancellation. Accept explicit UTC times only; reject duplicate fields/UIDs, oversized and incomplete calendars. Never silently replace the last readable edition on failures. Users select retained calendar editions; these are captures taken by this app, **not original historical data vintages**. Do not infer an actual release from a scheduled date. Public source links and last retrieval time remain visible. Additional verified RBI/MoSPI/Fed calendar parsers and original historical numerical-vintage archives remain distinct source coverage work, not inferred from this calendar.

Web and Android share reader/components. Device-only mode can view a saved snapshot and retained local edition selection; it cannot run a server worker. No fabricated calendar is seeded. Loading, empty, error/retry, keyboard selects and accessible status messages are required. Calendar refresh never calls an LLM. Tests use clearly synthetic fixtures and actual API/database paths; provider transport substitution is labelled.

## Approved automatic publication policies

Capture no longer requires per-story review when a qualifying source policy is explicitly approved. Operations Automatic research → Automatically add official stories supports fixed Fed/ECB press/PIB/BEA adapters only. A policy binds the exact source rights/endpoint and adapter-policy version, seven-day UI expiry (API maximum30 days), existing/future draft scope and review note. Named mode requires a different publisher from the preparer; both named role versions must remain enabled. Bootstrap uses its existing administrator authority. A disabled replacement policy retires publication permission. Merely enabling capture does not enable publication.

At each run the policy is re-admitted, retained raw bytes/hash and fixed source origin are verified, and at most50 qualifying deterministic news drafts pass through the existing publication revision method. Commit-time admission holds policy/identity locks, so expiry, rights changes, revocation or a newer source edition prevents publishing. Per-item immutable receipts record publication or explicit exclusion causes. New published versions enter ordinary Today/Explore/Stories feeds automatically. No arbitrary URLs, LLM-generated claims or regulated recommendations qualify. Missing/expired policies leave drafts for normal review; worker status reports exact published/excluded counts and safe causes. Pause stops future claims; an already claimed run may finish.

Automatic publication selects at most 50 current draft heads using the exact source prefix in PostgreSQL; it does not materialize the Operations inventory or historical revisions. Unattempted current versions precede retries, then retries use their latest attempt timestamp and stable item ID. Each exclusion appends an immutable attempt receipt, so rejected drafts rotate instead of permanently occupying the first batch. A newer item version is a fresh candidate. Successful edition receipts remain unique. E2E-API-1060 authors the regression with 60 unrelated heads, 50 malformed source drafts, a valid retained official draft and three batches, proving eventual publication and retry rotation. This is authored coverage, not an executed result.
