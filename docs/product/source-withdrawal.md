# Withdrawal of published reading

SOURCE-WITHDRAWAL-001 changes disclosure, not stored history. An editorial withdrawal creates the existing immutable edition. Public current/history responses retain a dated tombstone; title, summary, body, topics, related content and copied editorial notes are unavailable. A current withdrawal redacts all public history entries. After explicit republication, previously published editions can be read again, while withdrawal editions remain tombstones. Drafts never become public by implication.

Public evidence is a selected-edition projection, labelled as such. Its hash identifies the complete retained provider response, not the projection bytes. BEA keeps its narrower release-metadata excerpt. No public route returns a shared RSS body that can contain a withdrawn sibling. Protected operations retains exact original editions and raw evidence; no source record is rewritten or deleted. Canonical macro observations, accepted macro evidence, security identities and source-registry approvals have separate publication policies and are not implicitly withdrawn by changing a discovery item.

Source admission acquires discovery_items row SHARE locks before selecting current non-draft editions, and retains them through projection/evidence access. A read admitted before withdrawal may complete; a read waiting behind a committed withdrawal must not admit its text. Multi-source locks and ingestion are ordered by source ID. Private writes lock account before source and recheck current-clock authorization after waits. Library reads use an account SHARE lock and one admitted publication set. Repeatable-read financial exports lock account, then the authenticated session, before source admission; concurrent revocation is fenced and a session changed since the snapshot fails closed. Public source projection transactions must not use READ ONLY with row locks. Worker-control admission remains first when merged with the worker-health change. Reminder delivery selects at most 50 candidates, locks sorted available accounts and sources, then claims still-due reminder rows; source withdrawal and private cancellation therefore use compatible lock order.

Saved reading, reminder/notification responses, reminder replay and account export project withdrawn provider text into tombstones. Stored snapshots, positions, reminder states, request identity and versions remain intact. Users can remove saved entries, cancel reminders and mark notifications read. Own notes, minimal dated connection/inbox receipts, exact financial records and separately consented issued report copies are never erased implicitly. The old API122 expectation of exposing the withdrawn saved summary is intentionally replaced.

Readers expose an explicit Refresh reading action; known withdrawal removes original-source, evidence, media, related-context and create-connection actions. History remains a dated receipt, with safe navigation back to available reading. A new current read invalidates older detail/media responses. Saved and reminder views describe unavailable source content and retain user controls. Learning quizzes are independently authored; only associated published research is filtered. Assistance revalidates exact source editions after asynchronous selection before returning source text.

On device, highest-version non-draft history overrides older feed entries. All public/library/assistance projections share that resolver, including direct export. Local projection never changes stored user snapshots. The public snapshot exporter validates its collected source and media editions against a final admitted manifest before writing, and refuses an inconsistent export. Withdrawn text, evidence and media are omitted. An older disconnected installation cannot discover later server withdrawal until its dated bundle is replaced; previously downloaded personal files cannot be remotely recalled.

Acceptance covers actual isolated publication/withdrawal/republication, shared RSS siblings, current/history/evidence/media direct paths, source-lock wait ordering, private mutations/session expiry during waits, reminder replay/export, delayed assistance selection, snapshot collection races, unchanged underlying receipts, reader/Saved/learning navigation, escaped text and local persisted zero-network parity. Provider calls, migration, dependency installation, tests, builds, physical-device acceptance and gated commits are parent-controlled. Authored cases do not establish verification.
