## Deployment monitoring specification — 2026-09-15

Implement shared-PostgreSQL monitoring for every participating API process. Each process records anonymous minute request-counter deltas with stable receipt IDs; retries must not double count. Aggregate the last 15 minutes, show last persisted heartbeat and process count, and create durable incident episodes for server errors (at least 20 completions and at least 5% errors) and missing process heartbeats (over three minutes). Operators can acknowledge an incident without resolving it; recovery resolves it and recurrence creates a new episode. Keep seven days of samples and ninety days of resolved incidents. No request bodies, URLs, credentials, private account data or external notifications enter this pipeline.

Acceptance: actual stored samples drive aggregation; storage failures leave unknown/unavailable states, never a green fabricated status. Reads and acknowledgment recheck operator admission after database waits. Origin and admin permission protect acknowledgment. API/frontend boundary schemas reject unknown fields.
