## Implementation acceptance scenarios

For each future case, capture task/case ID, build/commit, exact run ID, API/web targets, browser/device/viewport, prerequisite dataset/source version, and expected versus actual outcome. Use isolated accounts with synthetic personal inputs through actual APIs; use actual permitted provider data for source integration. Synthetic failure fixtures are explicitly labelled. Never capture credentials, real private portfolios or operator secrets in screenshots/traces/reports.

## Test and automation rules

Use existing Playwright API/desktop/mobile projects and manual UI/report tooling. Add new worker/domain tests for time, ranking, lease/idempotency and precision where meaningful. Real source/provider integration needs explicitly configured access and approved sample scope; isolated deterministic tests use labelled fixtures. No placeholder pass, test-import side effect, background test watcher or auto-started production task.

For planning-only review, no migration/install/service change is needed. The standard user-invoked `pnpm sdlc "Plan mobile discovery and complete product experience"` requires the existing app/databases to be ready, runs format/check before local commit, then executes the existing suite; it never pushes. Future UX-ACC scenarios will appear in the UI only after their implementations and executable cases are authored.
